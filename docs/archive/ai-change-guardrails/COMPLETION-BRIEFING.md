# AI-CHANGE-GUARDRAILS 완료 브리핑

> 2026-09-07 작업 · 2026-09-08 머지 · 이슈/PR #152 / #153 · 브랜치 `#152`

## 작업 요약

이 저장소의 코드 상당 부분이 AI 를 통해 작성되는데, 지켜야 할 규칙 대부분이 `CLAUDE.md` 와 `docs/context/` 의 문장으로만 존재했다. 문장으로 적힌 규칙은 읽는 쪽이 기억해야 지켜지고, 어겨도 빌드는 통과한다. 세션이 바뀌면 앞 세션에서 얻은 교훈은 사라진다. 위반이 나올 때마다 지침에 금지 항목을 한 줄 더 붙이는 대응은 프롬프트만 길어지고 같은 위반이 재발한다.

기계가 판정할 수 있는 규칙을 실행 가능한 검사로 옮겼다. 편집 직후 · 작업 종료 · 빌드 · CI 네 지점에 걸어, AI 가 규칙을 읽었는지와 무관하게 어기면 실패하게 만들었다.

조사 과정에서 두 가지가 드러났다. **직접 작성한 Checkstyle 규칙 5종이 전부 경고 수준이고 `maxWarnings` 도 설정돼 있지 않아, `var` 금지도 광범위 예외 삼킴 금지도 한 번도 빌드를 중단시킨 적이 없었다.** 규칙이 있다고 믿고 있었을 뿐이다. 그리고 헥사고날 레이어 규칙은 문서로만 존재해, 도메인이 application 값 객체를 참조하는 위반이 이미 하나 들어와 있었는데 어떤 검사에도 걸리지 않았다.

이 작업은 워크플로우 게이트(discuss / plan)를 거치지 않고 대화 중 직접 구현했다. 그래서 설계 문서와 PLAN 산출물이 없고, 이 브리핑이 유일한 기록이다. 대신 구현 후 사후 검증을 두 라운드 돌렸다.

## 사후 점검에서 드러난 결함

구현 직후 "동작 확인"이라고 보고한 내용이 세 번 다 스크립트 직접 실행 결과였고, 실제 트리거는 확인한 적이 없었다. 판정 로그를 붙이고서야 아래가 드러났다.

| 결함 | 내용 |
|:---|:---|
| `SubagentStop` 미등록 | `Stop` 은 서브에이전트에서 발생하지 않는다. execute 단계는 Implementer 가 코드를 쓰므로 **가장 많이 생산되는 구간이 통째로 비어 있었다** |
| 커밋된 변경 미탐지 | 서브에이전트는 항상 커밋 후 종료 — 위 결함이 없었어도 "변경 없음"으로 통과했을 것 |
| 컴파일 실패 시 진단 없음 | 테스트 결과 XML 부재 시 원인을 전달하지 않고 "테스트 실패"로만 보고 |
| 종류 미상 종료 이벤트 | 서브에이전트 호출 1회에 `SubagentStop` 이 2번 발생하며 그중 하나는 에이전트 종류가 비어 읽기 전용 필터를 우회 |

## 컨벤션 위반과 지침 개선

이슈와 PR 이 GitHub 컨벤션 3항목을 어긴 채 만들어졌다 — 이슈 제목에 type prefix 부착, 라벨·담당자 누락, PR 본문 푸터.

원인은 `issue-commit-pr` 스킬이 상단에서 정본을 따른다고 밝혀 놓고 본문에 규칙을 다시 적어 둔 것이다. 그 사본이 정본과 어긋나 있었고(이슈 제목 형식 반대, 예시가 클래스명 노출, 라벨·담당자 누락), 실행 시 정본 대신 사본을 따랐다.

사본을 걷어내고 정본 위임으로 바꿨다. 정본에는 누락이 실제로 발생한 지점을 명시했다 — PR 생성·갱신 툴에 라벨·담당자 인자가 없어 별도 지정이 필요하다는 것, 푸터 금지는 세션 지시가 있어도 예외가 없다는 것.
