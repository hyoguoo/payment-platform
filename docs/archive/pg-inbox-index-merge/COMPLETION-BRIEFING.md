# pg_inbox index_merge·데드락 재현 — 완료 브리핑

> 실험: 2026-10-01 KST · 자료 이관: 2026-10-02

## 문제와 결과

주문 번호 UNIQUE 인덱스가 있는데도 승인 결과 UPDATE가 상태 인덱스를 함께 검색한 이유와,
서로 다른 주문 사이의 잠금 충돌을 확인했다. MySQL 8.0.46의 별도 실험 DB에 프로젝트
V1~V7 스키마와 완료 이력 50만 건을 구성했으며 인덱스 힌트는 사용하지 않았다.

- 처리 중인 행이 소수일 때 UNIQUE·상태 인덱스의 index_merge가 선택됐다.
- optimizer trace는 주문 번호 단독 비용 1.64349보다 병합 비용 1.23301을 낮게 평가했다.
- 실제 덤프에서 서로 다른 주문의 UPDATE가 같은 행의 PK·상태 인덱스 잠금을 엇갈려 보유·대기했다.
- 상태 인덱스를 `(status, updated_at)`으로 교체한 전후 각 5,000건 실행에서 첫 시도 데드락은 28 → 0건이었다.

각 조건 1회, 같은 DB에서 순차 실행한 결과다. 과거 전체 결제 실험의 데드락 163 → 0건과
완료 p99 73.1 → 9.3초를 재측정한 결과가 아니다. 당시 장애의 기록과 후속 DB 재현을 구분한다.
