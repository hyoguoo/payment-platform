# 테스트 관점

TDD의 테스트 목록을 만들 때 쓴다. 구현 전에 아래 관점마다 해당하는 케이스를 고르고, 해당 없으면 건너뛴다.
예외 케이스도 정상 경로처럼 실패를 먼저 확인한다.

| 관점 | 확인할 것 |
|---|---|
| 입력 경계 | null·빈 값·공백, 경계값과 그 ±1, 형식 오류, 타입 불일치(실수·문자열로 온 숫자), 특수문자·인코딩 |
| 상태 | 허용되지 않은 전이, 이미 처리된 대상, 없는 대상, 검사 순서 |
| 중복·재시도 | 같은 요청 두 번, 응답을 못 받은 뒤 재시도 |
| 동시성 | 같은 대상을 동시에 바꿈. 보호 장치(락·제약)를 빼면 테스트가 실패하는지 한 번 확인한다 |
| 부분 실패·복구 | 저장·외부 호출 실패 뒤 상태가 그대로인지, 재시작 뒤 복원되는지 |
| 프레임워크 경계 | 직렬화·타입 변환·설정은 단위 테스트가 거치지 않는다. 외부 계약의 오류 경로는 실제 설정으로 띄운 애플리케이션에서 한 번 확인한다 |
| 테스트 자체 | 기대값을 구현과 같은 로직으로 계산하지 않는다. 생성한 테스트 데이터가 의도한 경우를 실제로 담는지(중복·편향) 확인한다 |
