# context 문서 대조

`docs/context/`는 코드만 읽어서는 알기 어려운 프로젝트 지식을 둔다. 문서 목록과 각 문서가 다루는 범위는
[docs/context/README.md](../../../docs/context/README.md)에 있다. 이 스킬은 문서가 코드와 어긋난 곳을 찾아 맞춘다.

## 1. 대상 정하기

| 호출 | 대상 |
|---|---|
| workflow-ship | `git diff <기준 브랜치>...HEAD --stat`의 변경 파일과 README의 문서 범위를 대조해 영향받는 문서만 고른다 |
| 단독 요청 | 요청한 주제의 문서. "전체"면 README의 모든 문서 |

관련 없는 문서는 열지 않는다.

## 2. 대조

- 문서가 말하는 클래스, 패키지, 설정 키, 토픽 이름, 상태값이 지금 코드에 있고 설명대로 동작하는지 확인한다.
  `python3 scripts/check-agent-docs.py --strict`의 문서 식별자 대조가 존재 여부를 먼저 걸러 준다. 동작이 맞는지는 코드를 읽어 확인한다.
- 다이어그램은 노드와 화살표를 실제 호출 경로와 비교한다.
- 사실의 근거는 소스 파일과 줄만 인정한다. 다른 문서나 archive를 인용해 사실을 확정하지 않는다. 문서끼리 서로 인용하면
  낡은 서술이 정본처럼 굳는다.

## 3. 고치기

- 코드와 다른 서술만 고친다. 범위 밖의 문체 개선은 하지 않는다.
- 삭제·이름 변경된 구성요소는 문서에서도 지우거나 고치고, 새로 생긴 포트·어댑터·상태·함정은 해당 문서에 더한다.
- 다이어그램은 노드와 화살표만 실제와 맞추고 배치는 되도록 그대로 둔다.
- 문서 머리에 갱신 날짜나 갱신 이력을 쓰지 않는다. 이력은 Git과 archive가 가진다.
- 해결된 우려나 할 일은 [docs/TODOS.md](../../../docs/TODOS.md)에서 지운다. 일부만 해결됐으면 해결된 문장만 지우고 남은 한계는 둔다.
- 사람이 읽는 안내 문서(`docs/guides/`)는 결제 흐름이 바뀌었을 때 함께 고친다. 작성 기준은 [writing](../writing/SKILL.md)이다.

## 4. 보고

점검한 문서, 고친 문서와 고친 내용, 일치를 확인한 문서를 구분해 적는다. 열어 보지 않은 문서를 일치한다고 쓰지 않는다.
workflow-ship에서 호출됐으면 이 내용을 DESIGN의 "진행 기록"에 남긴다.
