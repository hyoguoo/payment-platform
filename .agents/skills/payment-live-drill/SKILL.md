# 결제 라이브 실측

요청된 로컬 테스트 환경과 시나리오를 확인하고 실제 동작을 기대 결과와 대조한다.
사용 가능한 도구와 로그인 상태를 먼저 확인한다. 알림 발송이나 관리자 상태 변경이 필요한
시나리오는 기존 요청이 그 동작까지 포함하는지 확인한다. 스킬 선택 자체가 외부 발송 권한은 아니다.

## 단계별 참고

| 단계 | 참고 |
|---|---|
| 스택·시드·권한·재개 | [setup](references/setup.md) |
| 성공·실패·재시도·동시성·장애 | [scenarios](references/scenarios.md) |
| 캡처 전 화면별 주의·기록 | [capture](references/capture.md) |
| HTML 리포트·열기 | [report](references/report.md) |

현재 단계의 문서만 읽는다. 재개할 때는 setup의 재개 절을 확인해 살아 있는 환경을 재사용한다.
구동은 [run-scenario.sh](scripts/run-scenario.sh), 동시 요청은
[run-concurrent.sh](scripts/run-concurrent.sh), 캡처는 [capture.sh](scripts/capture.sh)를 사용한다.
저장소 루트에서 실행할 때는 `.agents/skills/payment-live-drill/` 접두사를 붙인다.

## 관측과 판정

- 리포트의 화면 주장은 해당 상태가 보이는 캡처로 뒷받침한다. 운영자 화면에서 확인할 수 없어
  로그·DB·터미널로 대조한 내용은 그 근거와 관측 공백을 명시한다.
- 캡처 파일을 직접 열어 로그인 화면·빈 패널·누락된 스타일·어긋난 수치를 확인한다.
  파일 생성만으로 시나리오를 통과 처리하지 않는다.
- 예상과 다르면 원인을 조사하고 관측 사실과 추론을 구분한다. 요청에 결함 수정이 포함되면
  수정·검증하고, 조사만 요청되었으면 결함과 수정 방향을 보고한다.
- 시나리오별 기대·관측·판정·실행 명령을 남긴다. 재시도 과정은 시점별 캡처로 보여준다.
- 의미 있는 장면이 끝나면 중간 결과를 알린다. 대기는 가능하면 다른 준비 작업과 병행한다.
  사용자 로그인 같은 필수 입력이 없으면 그 단계만 대기하고 독립적인 작업은 계속한다.

## 산출물

`live-drill/`는 저장소 내부의 Git 무시 디렉토리다. 결과는 `report.html`, 캡처는 `originals/`,
명령 이력은 `captures.log`, 중단 시 메모는 `RESUME.md`에 둔다. 기존 PLAN이 있으면 함께 갱신한다.
캡처 이름은 `<순번>-<내용>.png`로 한다. 시간에 따른 변화는 같은 접두사에 순번을 이어 붙인다.

캡처는 기본 1440 폭·2배 해상도다. `CAPTURE_OUT_DIR`, `CAPTURE_WIDTH`, `CAPTURE_DELAY`로 조절하고
대시보드 렌더 시간을 확보한다. 리포트는 report 가이드대로 정적 서버에서 열어 검증한다.
완료 보고에는 결과물 경로, 실패·미검증 항목, 남겨 둔 실행 환경을 적는다.
