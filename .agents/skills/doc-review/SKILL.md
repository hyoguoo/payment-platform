# 문서 검수

요청한 문서와 범위를 확인하고 해당하는 관점만 적용한다.

- 문체: [위키·포스팅 작성 기준](../writing/references/style-guide.md) 7절의 평가 항목(자연스러움, 명확성, 구체성, 논리성, 간결성,
  정확성, 일관성, 절제)과 8절의 규칙. 브리핑·PR 본문이면 [공통 작성 기준](../../conventions/writing.md)을 쓴다.
- 기술 정확성: 클래스, 설정, 상태, 수치, 코드 예시를 실제 코드와 대조한다.
- 서술: 문제와 결론의 연결, 시간 순서, 중복, 같은 개념의 이름을 확인한다.
- 독자 이해: 필요한 배경 설명과 그림의 참여자·화살표 의미를 확인한다.

문제 위치, 근거, 수정 방향을 영향도 순서로 보고한다. 고칠 이유를 설명할 수 없는 문장은 지적하지 않는다(작성 기준 6절).
검수만 요청받았으면 수정하지 않는다. 작성·수정 작업의 일부라면 발견한 문제를 고치고 바뀐 부분을 확인한다.
고정 횟수의 반복 검토나 관점마다 별도 에이전트 호출을 요구하지 않는다. 확인하지 못한 사실은 "미확인"으로 적는다.
