# 코드 리뷰

사용자가 지정한 diff를 기준으로 검토한다. 지정이 없으면 `git status --short`, staged/unstaged diff,
미추적 파일을 확인한다. 워킹 트리가 깨끗하면 현재 브랜치와 기준 브랜치의 차이를 확인하고,
변경이 없는 경우 임의로 과거 PR을 선택하지 않는다.

[code-ready](../_shared/checklists/code-ready.md)의 해당 항목과 관련 소스·테스트를 대조한다.
상태·멱등성·재시도·보상·금액·민감정보·동시성이 바뀌면
`docs/context/PITFALLS.md`에서 관련 함정을 확인하고 실제 실패 경로를 추적한다.
테스트 결과가 없으면 미검증으로 표시하고, 리뷰만을 위해 무관한 전체 테스트를 반복하지 않는다.

실질적인 결함을 영향도 순으로 보고한다. 각 finding에 파일:라인, 발생 조건, 영향, 수정 방향을
포함한다. 취향과 추측을 결함으로 만들지 않는다. 발견이 없으면 그 사실과 검증 한계를 적는다.
검토만 요청받았으면 코드를 수정하지 않는다. 수정까지 요청받았거나 마무리 작업 중이면
승인된 범위에서 해결하고 바뀐 경로를 검증한다.

[공통 협업 방식](../../roles/README.md)에 따라 실질적인 검토는 reviewer에게 맡긴다.
결제 위험을 다루면 domain-expert도 같은 입력 범위로 독립 검토하고 결과를 통합한다.
이미 reviewer나 domain-expert로 호출된 서브에이전트는 직접 검토하고 다시 위임하지 않는다.
도구 부재나 상위 지침 제한으로 직접 검토할 때는 그 사실을 결과에 표시한다.
