# plan-ready 체크리스트

현재 계획에 관련된 항목만 적용한다.

# Gate checklist

## traceability

- [ ] 설계 결정 또는 요청 요구가 태스크로 연결되고 범위 밖 태스크가 없다.

## task quality

- [ ] 각 태스크의 변경 위치·입출력·객관적 완료 기준이 구체적이다.
- [ ] 실제 의존관계에 따라 순서가 정해져 있고 테스트용 Fake 등 선행 구현이 누락되지 않았다.

## TDD specification

- [ ] 행동 변경·버그 회귀에 관찰 가능한 결과를 확인하는 테스트가 계획되어 있다.
- [ ] 문서·단순 설정에는 산출물에 맞는 검증 방법이 있다.

## architecture fit

- [ ] 실제 레이어·서비스 경계를 지키며 존재하지 않는 관례를 가정하지 않는다.

## domain risk

- [ ] 설계의 상태 전이·멱등성·보상·동시성 위험이 구현과 검증 태스크에 반영되어 있다.

# Post-phase checklist

- [ ] PLAN과 STATE가 다음 실행 위치를 가리킨다.
- [ ] 커밋은 요청 범위에 포함된 경우에 처리했다.
