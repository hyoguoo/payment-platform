# 계획 구현

[workflow](../workflow/SKILL.md)의 범위를 따르고 STATE와 활성 PLAN에서 남은 태스크를 확인한다.
이전 완료 표시를 현재 코드·검증 근거와 대조한 뒤 의존 순서로 구현한다.
[공통 협업 방식](../../roles/README.md)에 따라 분리 가능한 구현 묶음을 implementer에게 맡긴다.
이미 implementer로 호출된 경우 맡은 범위를 직접 수행한다. 메인이 같은 파일을 동시에 고치지 않는다.

1. 해당 태스크의 관련 코드와 `docs/context/conventions/`의 필요한 규칙을 읽는다.
2. 행동 변경은 [테스트 규칙](../../../docs/context/conventions/testing.md)에 따라 재현 테스트와
   구현을 진행한다. 문서·설정 작업에는 그 산출물에 맞는 검사를 적용한다.
3. [AGENTS.md](../../../AGENTS.md)의 검증 범위에 따라 테스트·정적 분석을 실행한다.
   통과한 동일 상태의 검사를 이유 없이 다시 실행하지 않는다.
4. PLAN의 완료 결과에 변경 내용·실행한 검사·남은 제한을 기록하고 STATE의 다음 태스크를 갱신한다.

컴파일 오류나 명백한 회귀는 직접 해결한다. DB·빌드·포트 변경도 계획이나 요청에 포함되어 있으면
진행한다. 설계 결정이 필요한 범위 확장이 발견되면 조사 결과와 선택지를 제시하고,
그 결정에 의존하지 않는 작업을 계속한다. 실패한 선행 태스크를 완료로 표시하지 않는다.

커밋이 요청된 경우 [커밋 규칙](../_shared/conventions/commit.md)으로 논리적 단위를 기록한다.
모든 태스크가 완료되면 STATE에 ship 단계를 기록하고, 요청 범위에 마무리가 포함되면
[workflow-ship](../workflow-ship/SKILL.md)으로 이어간다. 중단 시 실제 재개 지점을 남긴다.
