# 구현

진행 범위와 STATE 기록은 [workflow](../workflow/SKILL.md)를 따른다. STATE와 DESIGN의 "태스크"·"진행 기록"에서
남은 태스크를 확인하고, 이전 완료 표시는 현재 코드와 검증 결과로 다시 확인한다.

## 태스크 루프

의존 순서대로 태스크마다 반복한다.

1. 관련 코드와 필요한 규칙 문서(docs/context)를 읽는다.
2. 구현한다.
   - tdd=true: 완료 기준을 확인하는 실패 테스트를 먼저 쓰고, 실패를 확인한 뒤 구현한다.
   - tdd=false: 산출물에 맞는 확인 방법(정적 분석, 빌드, 문서 검사)을 적용한다.
3. 태스크의 검증 명령을 실행한다. 같은 상태로 이미 통과한 검사는 이유 없이 다시 돌리지 않는다.
4. DESIGN의 태스크에 완료 결과(변경 파일, 실행한 검사와 결과, 남은 제한)를 적고 태스크 단위로 커밋한다.
   STATE의 다음 태스크를 갱신한다.

## 위임

DESIGN에 implementer 후보로 표시된 묶음은 implementer에게 맡긴다. 위임 내용: 태스크와 완료 기준, 관련 결정과
장애 시나리오, 허용 쓰기 범위, 검증 명령, DESIGN 갱신 권한 여부. 메인은 위임한 파일을 동시에 고치지 않는다.
결과를 받으면 변경 diff와 검증 결과를 직접 확인한 뒤 완료 처리한다.
이미 implementer로 호출된 경우에는 맡은 범위를 직접 수행하고 다시 위임하지 않는다.

## 변경 요청

- 개발자가 요구를 추가하거나 바꾸면 workflow의 [진행 중 변경 요청](../workflow/change-request.md)으로 수준을 정해 처리한다.
- 구현 중에 개발자에게 물어야 하는 범위 확장(discuss의 "반드시 묻는다")을 발견해도 같은 기준으로 처리한다.
  물을 필요가 없는 구현상의 추가 작업은 DESIGN에 태스크만 추가한다.

## 막혔을 때

- 컴파일 오류나 명백한 회귀는 직접 해결한다.
- 실패한 태스크를 완료로 표시하지 않는다. 같은 실패가 반복되면 원인과 시도한 것을 진행 기록에 남기고 보고한다.
- 종료 검증 hook에 막히면 전달된 실패를 고친다. 차단 한도에 걸려 통과됐더라도 남은 실패는 해결된 것이 아니다.
  hook 동작은 [AGENTS.md의 검증 hook](../../../AGENTS.md#검증-hook)을 따른다.

## 커밋과 다음 단계

커밋 시점과 형식은 [Git 규칙](../../conventions/git.md#커밋)을 따른다.
모든 태스크가 끝나면 STATE를 ship 단계로 바꾸고, 개발자가 범위를 구현까지로 제한하지 않았으면
[workflow-ship](../workflow-ship/SKILL.md)으로 이어간다. 중단할 때는 DESIGN의 "진행 기록"에 실제 재개 지점을 남긴다.

개발자가 중단을 요청했는데 코드가 미완성 상태(실패 테스트를 먼저 쓴 직후 등)라면 `.agents/hooks/verify-pause.sh "<사유>"`로
종료 검증을 일시정지한다. 진행 기록과 보고에 일시정지 사실과 남은 실패를 적는다. 재개해서 코드를 고치면 자동으로 풀린다.
