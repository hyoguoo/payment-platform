# 구현 계획

[workflow](../workflow/SKILL.md)의 진행 범위를 따른다. 활성 설계가 있으면 그 결정과
현재 코드를 대조한다. 설계 문서가 없는 계획 요청은 제공된 요구를 근거로 작성하고 가정을 표시한다.

`docs/<TOPIC>-PLAN.md`에 목표, 관련 설계, 진행 체크박스, 태스크별 변경 위치·의존성·완료 기준을
기록한다. 실행 순서는 실제 코드 의존관계로 정한다. 포트·레이어 이름을 일률적인 의존 화살표로
해석하지 않는다. 각 태스크는 독립적으로 검증 가능한 크기로 나눈다.

- `tdd=true`: 비즈니스 로직·상태 전이·버그 회귀. 검증할 입력과 관찰 가능한 결과를 정한다.
- `tdd=false`: 문서·상수·단순 선언 등. 적절한 정적 검사나 확인 방법을 정한다.
- `domain_risk=true`: 상태 전이·멱등성·정합성·트랜잭션·민감정보·PG 연동·동시성을 바꾸는 태스크.

기존 계획의 플래그는 보존한다. 태스크별 테스트 명령을 영향 범위에 맞춰 적고, 완료 결과와
리뷰 처리 기록을 실행 중 채울 수 있게 한다. 설계 결정이 태스크에서 누락되거나 범위 밖 태스크가
추가되지 않았는지 [plan-ready](../_shared/checklists/plan-ready.md)로 확인한다.

STATE에 계획 경로와 다음 태스크를 기록한다. 계획만 요청받았다면 계획을 전달하고,
구현까지 요청받았다면 [workflow-execute](../workflow-execute/SKILL.md)로 이어간다.
