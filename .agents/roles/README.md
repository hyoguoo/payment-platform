# 공통 에이전트 운영

Claude Code와 Codex는 같은 [AGENTS.md](../../AGENTS.md), 스킬, 역할 본문을 사용한다.
역할·모델 메타데이터의 정본은 [roles.toml](../roles.toml)이다.
도구별 설정은 `python3 scripts/sync-agent-configs.py`로 생성하고 직접 수정하지 않는다.
검사만 할 때는 `python3 scripts/sync-agent-configs.py --check`를 쓴다.
생성 파일과 실행 설정은 도구의 기본 탐색 경로인 `.claude/`·`.codex/`에 둔다.
두 경로는 실제 디렉토리이며, `.claude/skills`만 공통 스킬을 가리키는 상대 링크다.

## 역할과 배차

| 역할 | 맡기는 일 | 공통 본문 |
|---|---|---|
| implementer | 분리 가능한 구현 태스크·리뷰 수정 묶음 | [implementer.md](implementer.md) |
| reviewer | 설계·계획·코드의 요구 충족·회귀·테스트 누락 검토 | [reviewer.md](reviewer.md) |
| domain-expert | 상태·멱등성·동시성·PG 실패·보상·금전과 재고 정합성 검토 | [domain-expert.md](domain-expert.md) |

작은 문구·설정 수정은 메인이 직접 한다. 독립 작업으로 나눌 수 있는 구현은 implementer에게 맡긴다.
실질적인 설계·코드 검토와 토픽 완료 검토는 reviewer에게 맡기고, 결제 위험이면 domain-expert도
포함한다. 도메인과 무관한 지침·문서 정비에는 domain-expert를 호출하지 않는다.

각 호출에는 사용자 목표, 대상 파일·diff 기준, 필요한 설계 결정과 체크리스트, 허용 쓰기 범위,
검증 범위를 제공한다. 미커밋·미추적 변경을 빠뜨리지 않는다. 쓰기 작업은 겹치지 않게 나누고
의존 작업은 순서대로 처리한다. 두 검토자는 같은 변경 스냅샷을 보고 서로의 결론을 입력받지 않는다.
검토 중인 파일을 바꾸면 결과 수집 시 최신 diff와 대조하고 달라진 부분만 다시 확인한다.

메인이 결과를 근거와 대조해 통합하고 필요한 수정·검증을 마친다. 서브에이전트는 재위임하지 않는다.
전체 동시 실행은 메인 포함 최대 4개를 기본으로 하며 현재 런타임 한도가 더 작으면 그 한도를 따른다.

## 모델 선택과 실행 환경

메인 모델은 사용자의 선택을 유지한다. 기본 구현은 균형형·medium, 일반 검토는 균형형·high,
도메인 위험 검토는 최고 성능 계열·high를 사용한다. 구체 모델과 effort는 `roles.toml`에 있다.
서로 다른 제공자의 같은 effort 값이 동일한 성능·비용을 뜻하지는 않는다.

- Claude Code: `.claude/agents/`의 해당 이름으로 호출한다. 모델 alias는 제공자별 최신 권장 버전을 따른다.
- Codex CLI: `.codex/agents/`의 같은 이름으로 호출한다. 설정 파일에는 모델과 reasoning effort를 함께 둔다.
- 역할 이름을 받지 않는 Codex 실행 도구: 해당 `.codex/agents/<role>.toml`의 공통 지침을 전달하고
  지원되는 spawn 인자에 model과 reasoning effort를 지정한다. 전체 대화 fork가 모델 override와
  양립하지 않으면 최소 문맥을 전달하는 새 에이전트로 호출한다.
- 지정 모델이 제공되지 않으면 사용 가능한 메인 모델로 같은 역할을 수행하게 하고 변경 사실을 알린다.
  독립 호출 자체가 불가능하면 메인이 직접 처리하며, 완료 보고에 독립 검토 미실시를 구분한다.
- 모델 사용량·인증·권한 문제가 반복되면 같은 호출을 반복하지 않는다. 해당 작업의 가능한 부분을
  진행하고 남은 제약을 보고한다. 접근 권한·요금제·안전 설정을 자동 변경하지 않는다.

검토 역할은 두 도구 모두 파일을 수정하지 않는다. Codex 역할 설정은 `read-only` sandbox를
기본으로 두지만 호스트의 실행 옵션이 우선할 수 있다. Claude의 Edit·Write 제외도 Bash까지
쓰기 불가능하게 만드는 보장은 아니다. 실제 도구 권한을 확인하고, 변경을 만드는 검증은
구현 담당이나 메인에 요청한다.

## 사용자 경험

“설계 논의”, “계획 세워줘”, “구현해줘”, “리뷰해줘”, “마무리해줘”처럼 같은 자연어로 요청한다.
진행 보고는 현재 작업과 의미 있는 결과를 한국어로 짧게 전달한다. 내부 모델명·호출 과정은
선택이 바뀌거나 문제가 있을 때만 설명한다. 역할마다 별도 승인 질문을 만들지 않는다.
완료 보고는 결과·검증·남은 제한과 실제 파일 위치를 전달한다. 태스크 ID에는 내용을 함께 적는다.

스킬 이름도 동일하다. 명시 호출 표기만 Codex의 `$review`, Claude의 `/review`처럼 다를 수 있다.
모델의 답변·속도·도구 UI를 동일하게 보장하지 않는다. 훅은 도구별 기능이므로 그 실행 여부로
완료를 판정하지 않고 공통 검증 기준과 실제 검사 결과를 사용한다.
